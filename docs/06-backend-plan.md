# 06 — Backend plan (Laravel 13 API + existing React app)

Status: decided 2026-11-12. Supersedes the Inertia choice in `02-architecture.md` for the transport layer only;
the domain layer, data model and deployment shape there still apply.

## Decision

Keep the React 19 app as-is and put a **Laravel 13 JSON API** behind it, served from the same origin.

- Auth: Laravel session cookies via **Sanctum SPA mode** (`/sanctum/csrf-cookie`, `POST /login`). No tokens, no CORS.
- Laravel serves the built SPA: `public/build/*` (laravel-vite-plugin) and a catch-all route that returns
  `resources/views/app.blade.php`. One deploy artifact, same Apache vhost, `DocumentRoot /var/www/html/hr/public`.
- The zustand stores stay the pages' interface. They become a **sync layer**: hydrated from the server at sign-in,
  mutated optimistically, confirmed or corrected by the server response. Server is the source of truth.
- Why not Inertia: 60+ pages already depend on store selectors and synchronous store actions. Rewriting them to
  props + `router.post` is a full rewrite with no product gain. The API also serves the future mobile app.
- Realtime: **polling** `GET /api/sync?since=<cursor>` every 30 s now; Reverb later behind the same `applyPatch`.
- Chat is out of scope for this phase: the chat store stays in-memory, nav item stays, labelled "preview".

## Conventions (every agent follows these)

- **IDs are UUIDs** (char 36) on every table, generated by the client for optimistic inserts and accepted by the
  server (`HasUuids`; controller accepts optional `id` and validates uuid + uniqueness). Matches `Id = string`.
- JSON shape == `resources/js/types/index.ts`, snake_case, dates as `Y-m-d`, datetimes as ISO-8601 with offset in
  `Asia/Dhaka` (`config('app.timezone') = 'Asia/Dhaka'`). API Resources are the only place rows are serialised.
- Money as integers (BDT, no paisa) — same as the mock. Minutes/seconds as integers.
- Every mutation endpoint returns a **patch**: `{ "changed": { "<collection>": [rows] }, "deleted": { "<collection>": [ids] } }`.
  Collections are named exactly as the store slices (`employees`, `users`, `attendance_days`, `time_segments`, …).
  The client applies the patch generically. Validation errors are 422 with Laravel's default shape.
- Authorization: Policies per model, role from `users.role`. Abilities list (TS `Ability`) is computed by
  `App\Support\Abilities::for(User)` and returned by `/api/me`. Team lead scope = employees whose team's
  `lead_employee_id` is the viewer. HR/management see all.
- Business rules live in `app/Domain/<Module>/Actions/*` (invokable classes), controllers are thin.
  Port the rules from the mock stores one-to-one, including validation messages.
- Audit: `spatie/laravel-activitylog` on approvals and money changes; the mock's "History"/events panels read it.
- Tests: Pest feature tests per endpoint (happy path + one policy denial each). SQLite in-memory.
- Local dev: `php artisan serve` (port 8000) + `pnpm dev` (Vite 3000, proxied by laravel-vite-plugin). Sqlite file db.

## Sync layer (resources/js/sync)

- `client.ts`: `api.get/post/patch/delete`, adds `X-XSRF-TOKEN`, JSON, throws `ApiError{status, errors}`.
- `bootstrap.ts`: `GET /api/bootstrap` → one JSON with every collection the viewer may see, plus `me`, `abilities`,
  `policy`, `server_time`. `hydrateAll(snapshot)` sets every store slice. Called after login and on reload (session cookie).
- `patch.ts`: `applyPatch(patch)` merges rows by id into the right store, removes deleted.
- `mutate.ts`: `mutate(storeUpdate, request)`: apply optimistic update, send request, `applyPatch(response)`;
  on 4xx toast the message and re-bootstrap the affected collections (simple rollback).
- Store actions keep their names and signatures. Return values stay synchronous where the mock computed the
  result locally (people, work, leave, billing edits). Attendance transitions (`startWork`, `startBreak`, `endDay`,
  `setCurrentTask`, `heartbeat`) and payroll (`draftRun`, `recompute`, approvals) **await the server**: the
  server owns the clock and the money; callers are updated accordingly (few call sites).
- `localStorage` data persistence (`persist.ts`) is removed; only theme/sidebar/session prefs remain.
- `poll.ts`: every 30 s while signed in → `GET /api/sync?since=` → `applyPatch`. Server returns rows with
  `updated_at > since` from the viewer-scoped collections.

## Attendance on the server (authoritative)

- `POST /login` authenticates, then runs `StartWork` (same rules as the mock: late minutes vs policy grace,
  reopen after `ended` only with `confirm_overtime=true`, returns `needs_overtime_confirm`).
- `POST /logout {mode: break|end_day, break_category}` runs `StartBreak` or `EndDay`, then logs out.
- `POST /api/attendance/break`, `/resume`, `/end-day`, `/current-task`, `POST /api/heartbeat` (every 60 s;
  response = today's day + segments + server_time so the client resyncs its timers).
- `attendance:sweep` scheduled every minute: `working` days whose `users.last_seen_at` is older than
  `idle_timeout_minutes` get an `offline` break segment from the last beat (same semantics as `reconcileOffline`);
  on the next heartbeat the server closes it and reopens work. Also marks `absent`/`holiday`/`on_leave` days at 23:59.
- Regularizations: request + decide endpoints, lead/HR policy.

## Modules and endpoints (names mirror the store actions)

People: `GET/POST /api/employees`, `PATCH /api/employees/{id}`, `POST .../status`, `.../salary-structures`,
`.../bank-account`, `.../documents`, `.../assets`, `PATCH /api/checklist-items/{id}`, `POST /api/employees/{id}/reset-password`,
`POST /api/account/password`. Onboarding creates `users` row with temp password `welcome123` and `must_change_password=1`.
Work: projects CRUD, members, columns (add/rename/reorder), tasks CRUD, `POST tasks/{id}/move`, subtasks, comments,
attachments (multipart → `storage/app/attachments`), activity read.
Leave: `POST /api/leave-requests`, `.../approve-lead`, `.../approve-hr`, `.../reject`, `.../cancel`, balances computed server-side.
Payroll: `POST /api/payroll/runs {year, month}`, `.../recompute`, `.../submit`, `.../approve`, `.../pay`,
adjustments add/remove. Calculator ported from `mock/db/payroll.ts` `calcItem` into `PayrollCalculator` as a pure class
(the improvement wave will extend it). Payslip PDF via dompdf at approve time → `payslip_path`.
Billing: clients, invoices (lines, send assigns the next number `VIV-YYYY-NNNN`, payments, void, overdue sweep via
scheduler), contractor claims (generate from task_time_entries, submit/verify/approve/pay).
Inbox: Laravel database notifications → `GET /api/notifications`, mark read. Fired by the leave/claim/payroll/regularization actions.
Platform: `GET /api/me`, `GET /api/bootstrap`, `GET /api/sync`, `GET /api/policy`.

## Deploy (vivadev)

MySQL db `vivacom_hr` + user; `.env` production; `composer install --no-dev`; `php artisan migrate --force --seed
--class=ProductionSeeder`; `pnpm build`; `storage:link`; cron `schedule:run` every minute; `config:cache`,
`route:cache`. Apache vhost already points at `public/`. Queue driver `database` with a supervisor worker is
optional (PDF generation runs sync in this phase).
